# 小醒 DeepSeek 全章节问答核验

## 页面与接口对应

`App` 将当前主路由传给 `XiaoxingAssistant`，助手将该路由放入同源 `/api/xiaoxing/chat` 请求。Node 问答接口允许 `entry/model/action/state/spread`；`state` 为动作章下的八态页面，`spread` 为传播地图章。服务端先使用当前章节筛选本地知识，模型只允许依据提交的材料回答，并由 Node 校验来源编号。

此前FAQ未命中时接口立即返回本地答案，用户询问“动作章节展示了什么内容？”得到 `reason=not-covered`，没有进入模型。这属于章节概括问题的检索缺口。当前调整为：检测到无具体知识条目时，把当前章节导览作为唯一章节材料送给 DeepSeek；如果模型仍无法依据资料回答或来源校验失败，保留本地未收录兜底。

## 实际核验

最新主线在本机 `http://127.0.0.1:5174/` 运行，使用隔离工作区忽略的 `.env.xiaoxing.local`。五个页面上下文分别向同源 API 提交了真实问题，全部 HTTP 200 且 `mode=online`：

| 页面上下文 | 核验问题 | 结果 |
| --- | --- | --- |
| `entry` | 首页介绍的醒狮文化有哪些特点？ | 在线，4个可信来源 |
| `model` | 醒狮狮头有哪些常见结构部件？ | 在线，2个可信来源 |
| `action` | 动作章节展示了什么内容？ | 在线，1个可信来源；使用章节导览材料 |
| `state` | 醒狮八态分别是什么？ | 在线，2个可信来源 |
| `spread` | 地图怎么从广东看到中国和世界？ | 在线，1个可信来源 |

当前本机默认开发端口 `5173` 仍被F盘原工作区占用；它运行在小游戏分支`codex/craft-mini-game-entry`，提交`d387b43`，本地没有DeepSeek密钥文件，且有用户未提交改动。本轮保留该工作区不动，最新集成版本运行在`5174`。不要将`5174`描述成外网网址。

## 部署边界

DeepSeek密钥只由Node服务读取，不进入浏览器包、Git或EXE。本轮测试基于GitHub `main`基线`65c8716`及工作区中的本次改动；GitHub Pages API返回404，仓库当前没有`main`工作流运行记录。公开网站仍需配置能够运行Node处理器的主机，或让同源 `/api/xiaoxing/chat` 反向代理到该服务。旧EXE和公开站点本轮均未部署或打包。
