# 标准记忆与 Git 初始化

## 目标与完成范围

用户明确指定 standard。依个人技能 3.2.1 先预览再应用初始化，工程内形成独立协议、README 导航、五页实质状态、六类日志目录及独立维护脚本。状态按当前源码、配置、正式设计文档和实际验证 JSON 填写，不复制虚构历史。

原先工程无 Git 仓库，本轮建立本地 `main`。根 `AGENTS.md` 接入新会话读取协议，并保存“每次完整对话的修改都要提交”的持续约束：本轮改动检查后提交，最终回复给出提交号；无变更不造空提交；保全其他任务改动。

沿用 `.gitignore` 排除依赖、构建输出和临时日志，原始 `.blend`、网页 GLB、图片、源码及验证资料纳入初始版本。新增 `.gitattributes` 统一文本与 Windows 启动脚本换行并标识二进制资源。未配置远程和推送，不扩大授权。

## 核实与验证范围

- 环境：Windows / PowerShell，2026-10-26。初次编写前无 Git revision，包含本日志的首次提交承载当前基线；最终提交号用 `git log -1 --oneline` 读取，避免日志自引用提交号。
- 实际执行技能初始化预览与 `--mode standard --apply`，再使用项目工具统一刷新索引和严格检查；实际退出结果在本轮工具输出中核对。
- 严格检查实际退出码为 0：9 页，`errors: []`、`warnings: []`；启动读取量 11,716 字符，低于 16,000 字符预算。人工核查五页实质内容与来源也通过。
- 验收入口：`python wiki_memory/工具/memory.py index --project . --apply`、`python wiki_memory/工具/memory.py check --project . --require-ready`。严格检查替代普通检查；工具结构通过之外，人工逐页核对事实、来源、恢复入口与约束。
- Git 验收：检查暂存差异与文件清单，再提交；交付前检查 HEAD、`git status --porcelain` 和跟踪列表，确认记忆、源码与资产纳入，依赖/构建目录未纳入。
- 本轮没有修改产品代码，不为写记忆重跑业务测试。之前六章开发/生产浏览器结果保留在 `artifacts/enrichment/`，属于 Git 建立前的本地工作区验证。
