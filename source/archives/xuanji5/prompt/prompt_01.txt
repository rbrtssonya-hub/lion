# 项目任务：广府醒狮交互式信息可视化拆解展位

## 一、项目目标

请在当前已有的 React + Vite + Three.js 网页项目中，完善广府醒狮文化信息可视化页面。

这不是一个重新设计整个网站的任务，而是在现有页面基础上，完成右侧信息可视化展位、六张 ImageGen 拆解图片、部件讲解浮窗以及相应的交互逻辑。

开始修改之前，必须先检查现有项目结构、页面组件、图片资源、醒狮模型资源和底部导航的实现方式。理解现有代码后再实施，尽量沿用现有组件、状态管理、样式体系和资源路径。

不要直接重建项目，不要删除现有功能，不要重新制作醒狮模型，也不要随意改变左侧已经完成的主视觉。

## 二、核心设计理念

整个页面采用两层信息体验。

第一层是视觉浏览层：

- 左侧继续展示现有的醒狮主体或当前选中的局部特写。
- 底部继续保留六个部件导航。
- 右侧原本的绿色占位区域改为信息可视化拆解图片展位。
- 右侧在默认状态下只展示图片，不出现标题、正文、图注、说明、按钮或其他文字 UI。
- 图片应当具有足够高的美术质量，像一张经过专业设计的文化展陈信息图，而不是普通商品图片或程序生成的技术草图。

第二层是深入阅读层：

- 用户点击右侧拆解图片后，弹出与当前部件对应的文化讲解浮窗。
- 浮窗中可以展示较丰富的中文内容，包括结构组成、造型特点、材质与工艺、视觉功能、文化内涵以及在醒狮表演中的作用。
- 用户可以在浮窗中阅读详细内容，关闭浮窗后返回原页面。
- 浮窗中的文化文字不应直接显示在右侧展位上。

设计原则：

**左侧展示醒狮的视觉形态，右侧展示醒狮的视觉结构，浮窗负责解释醒狮的文化内涵。**

如果当前 Codex 执行环境无法调用 ImageGen，请明确报告这一能力缺失，不要声称已经生成图片，也不要偷偷改用程序绘图代替。

### 3.3 六张图片的统一规范

六张图片必须分别调用 ImageGen 生成，不能一次生成一张包含六个小图的拼图，再将其当成六张独立资产使用。

统一要求：

1. 竖版构图，优先采用约 2:3 的纵向比例，适配右侧较高的展位。
2. 使用暖米白、象牙白或浅暖灰的纸张质感背景。
3. 主体采用高质量三维渲染与精细的真实材质表现。
4. 以醒狮红、暗朱红、暖白、旧金色和低饱和青绿色作为主要色彩。
5. 允许使用细腻的朱红色辅助线、轮廓线、结构引线、圆形放大视窗和淡淡的设计草图。
6. 采用高端文化展览、设计研究档案和精致产品拆解图的视觉语言。
7. 保持足够的留白，让主要部件具有清晰的空间关系。
8. 六张图应使用统一的光照、纸张背景、线条风格和配色体系，但构图与可视化方法必须根据各自部件的特点进行变化。

严格禁止：

- 生成可读文字、中文标题、英文标题、数字编号、图例、品牌标志或水印。
- 生成网页按钮、浏览器界面、卡片式 UI 或整张网页截图。
- 在图中出现大面积绿色占位矩形。
- 使用低质量、模糊、过度塑料化或过于卡通的主体。
- 将六张图设计成完全相同的构图，只替换中心物体。
- 使用程序绘制复杂的信息图来冒充 ImageGen 生成的成品。

图片中可以有精致的结构引线和辅助几何线，但不要出现文字标签。所有准确的部件名称与文化说明均由网页浮窗负责。

如果生成结果出现错误文字、明显变形或不符合现有模型的装饰，应重新生成并检查，不能直接使用有明显问题的成品。

## 五、右侧信息可视化展位的网页实现

右侧区域是整个任务的视觉重点之一。

请定位现有页面中的绿色占位容器，将其替换为一个图片展位组件，例如 `LionBreakdownStage`。

组件名称可以根据项目现有命名规范调整。

### 5.1 默认状态

右侧展位只展示当前选中部件对应的一张 ImageGen 图片。

例如：

- 选中“眉目”，展示 `01-mei-mu.png`。
- 选中“额冠”，展示 `02-e-guan.png`。
- 选中“繁须”，展示 `03-fan-xu.png`。
- 选中“织锦”，展示 `04-zhi-jin.png`。
- 选中“云边”，展示 `05-yun-bian.png`。
- 选中“口齿”，展示 `06-kou-chi.png`。

右侧展位不得出现额外的可见文字。

不添加图片标题、说明文字、序号、图注、操作提示、标签、按钮或装饰性文案。

鼠标悬停时可以采用非常轻微的缩放、亮度变化或轮廓变化，让用户感知图片可以交互，但不要在图片上叠加明显的文字提示。

### 5.2 图片显示规则

- 图片应完整显示，不要因为容器裁切而丢失主要拆解部件。
- 优先使用适当的 `object-fit: contain` 或等效的完整适配方案。
- 保留统一的暖米白背景和精致的视觉边界。
- 图片比例变化时，保持主体构图稳定。
- 不要重新绘制图片中的复杂线条、材质和拆解结构。
- 使用真实图片资源，不得用 CSS 渐变、SVG、Canvas 或 Three.js 重新构造图片内容。

程序只负责展示和交互，不负责创造复杂图像。

### 5.3 点击交互

点击右侧整张拆解图片，打开当前选中部件对应的文化讲解浮窗。

整张图片都应可点击，不能只设置一个很小的热点，导致用户难以触发。

可以使用图片外层的可访问交互容器实现点击功能。

如果后续能够根据生成图片中清晰分离的组件可靠地设置透明热区，可以进一步支持点击具体子部件；但这不是首要任务，不要为了实现复杂热点而牺牲稳定性或擅自绘制可见标签。

默认要求是：点击整张图即可进入当前部件的详细讲解。

## 六、文化讲解浮窗

请实现一个具有高品质文化展陈视觉风格的浮窗，而不是浏览器默认弹窗，也不是简单的 Toast 提示。

建议使用居中的模态浮窗，带有柔和的背景遮罩、轻微的背景模糊和克制的进入动画。

### 6.1 浮窗布局

桌面端可以采用左右双栏布局：

- 左侧约占 40%：展示当前部件对应的信息可视化拆解图片，作为视觉锚点。
- 右侧约占 60%：展示详细文化讲解。
- 整体宽度建议约为视口的 75%—85%，同时设置合理的最大宽度。
- 高度不得超出屏幕可用区域，正文区域允许独立滚动。
- 标题区域与正文区域应有清晰的层级关系。
- 关闭按钮应易于找到，但不能喧宾夺主。

移动端改为纵向布局，保证图片与正文都可以完整查看。

浮窗内部的文化文字可以较为丰富，但不要把所有内容堆成一大段。应通过标题、短段落、细分章节、重点语句和适当的留白组织阅读节奏。

### 6.2 浮窗内容结构

每个部件至少包含以下内容模块：

1. 部件名称与简短导语。
2. 形态构成：解释该部件在当前模型中的外观与组成。
3. 造型功能：解释该部件如何参与醒狮整体的形象表达。
4. 材质与工艺：介绍可确认的材质特征、装饰方式和视觉质感。
5. 文化观察：解释其与广府醒狮审美、民俗装饰和表演文化之间的联系。
6. 细节观察：指出观众可以从模型中进一步观察的具体特征。

文化内容应当有实际信息量，不要反复使用“精美”“生动”“独特”等空泛形容词凑字数。

特别注意：不能把对当前模型的视觉推测直接写成已经得到证实的历史事实。对于特定纹样的象征寓意、工艺来源和具体制作机制，如果没有可靠依据，就应采用审慎的表述，或只讨论可观察到的造型特点。

### 6.3 六个部件的讲解方向

#### 眉目

重点解释：

- 红色眉部绒毛、眼眶装饰、眼部主体之间的层次关系。
- 软质绒毛、光滑眼部表面与金属质感装饰形成的视觉对比。
- 夸张的眼部造型如何增强醒狮的表情表现力。
- 眼部细节如何影响整只醒狮的精神面貌和视觉焦点。
- 传统舞狮审美中对神态表现的重视。

避免将醒狮眼部简单解释成真实动物眼睛的解剖结构。

#### 额冠

重点解释：

- 中心装饰、环形饰件、珠饰与织锦底层之间的组合关系。
- 额冠如何形成醒狮头部的视觉中心。
- 环形、对称和层叠结构如何组织装饰层次。
- 金属质感、彩绘和织物之间的视觉关系。
- 传统民俗装饰中繁复装饰与整体形象之间的联系。

不要在没有依据的情况下，为每一个装饰环或珠饰指定固定的吉祥寓意。

#### 繁须

重点解释：

- 白色繁须、毛束和红色绒毛边饰的层次关系。
- 毛发的长度、密度、方向和弯曲如何塑造体积。
- 白色与红色的对比如何强化醒狮头部的视觉层次。
- 繁须在整体轮廓、表情和动态观感中的作用。
- 实际表演中柔性装饰可能呈现的摆动与流动效果。

区分当前三维模型的材质表现与真实醒狮道具的制作工艺，不要把推测写成确定事实。

#### 织锦

重点解释：

- 模型中实际存在的纹样、颜色和布料结构。
- 纹样单元如何重复、排列并形成整体图案。
- 红、金、青绿等颜色如何形成视觉节奏。
- 织锦如何丰富醒狮大面积红色表面的层次。
- 传统织物装饰与民俗审美之间的关系。

如果无法确认具体工艺是织造、刺绣、印花还是三维贴图，应以可观察的纹样和材质表现为主，不得擅自断言。

#### 云边

重点解释：

- 红色波浪形绒毛边饰的轮廓与排列方式。
- 曲线的起伏和重复如何产生装饰节奏。
- 边饰如何分隔醒狮身体上的不同视觉区域。
- 线条、绒毛和织锦之间如何形成材质对比。
- 实际云纹与云形轮廓装饰之间的区别。

不要将所有波浪形边饰都直接认定为传统云纹。

#### 口齿

重点解释：

- 口部轮廓、牙齿、舌部装饰和周围繁须之间的关系。
- 红色口部与暖白牙齿、白色毛发之间的对比。
- 口部如何参与醒狮表情的塑造。
- 如果当前模型支持口部动画，可以说明开合状态与表演表现之间的关系。
- 口部装饰如何与整只醒狮的视觉风格相协调。

如果模型没有可动结构，不要虚构真实道具的机械开合机制。

## 七、交互状态与代码结构

请使用清晰、可维护的组件结构，具体名称可根据现有项目调整。

可以参考以下职责划分：

- `LionBreakdownStage`：负责右侧图片展示和点击交互。
- `LionDetailModal`：负责浮窗布局、显示、关闭和正文滚动。
- `lionBreakdownData`：保存六个部件的图片路径、标题、导语和讲解内容。
- 现有页面组件：负责同步底部导航、左侧主视觉与右侧展位的当前选中状态。

不要为了这些功能引入不必要的大型依赖。如果项目已有动画库，可以沿用；否则使用轻量的 CSS 过渡即可。

交互要求：

1. 点击底部任一部件，左侧现有内容和右侧拆解图同步切换。
2. 点击右侧图片，打开当前部件的浮窗。
3. 点击关闭按钮，关闭浮窗。
4. 点击浮窗以外的遮罩区域，可以关闭浮窗。
5. 按下 Escape 键，可以关闭浮窗。
6. 打开浮窗时，不能改变当前选中的部件。
7. 关闭浮窗后，应返回打开前的页面状态。
8. 浮窗打开时，避免背景页面继续响应不必要的滚动操作。
9. 交互元素应具备基本的键盘可操作性、可访问名称和清晰的焦点状态。
10. 动画应轻柔克制，并兼容减少动态效果的系统偏好。

不要在右侧展位中额外添加显眼的交互控件。所有较复杂的阅读和说明都放在浮窗中。

## 八、视觉与排版要求

整套页面应延续现有的广府醒狮视觉语言：

- 暖米白纸张背景。
- 醒狮红与暗朱红。
- 旧金色、暖铜色。
