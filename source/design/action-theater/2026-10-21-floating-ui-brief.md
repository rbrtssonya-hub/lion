# Codex 补充要求：VR悬浮UI必须实时响应相机变化

## 一、最高优先级：禁止UI响应延迟

目前《四面观狮》具有360°旋转视角功能。

所有悬浮UI必须能够实时感知相机变化。

**用户开始拖动相机的第一帧，UI就必须开始响应。**

不得采用以下方式：

- 等待鼠标停止500ms再更新UI。
- 使用 setTimeout 延迟判断当前观察的巨幕。
- 通过300—500ms的动画让UI缓慢追赶相机。
- 每隔固定几百毫秒才检测一次相机方向。
- 因为等待视频加载而阻塞UI状态更新。

上一版提示词中的500ms观察等待机制在本任务中取消。

## 二、严格区分空间响应与视觉动画

### 1. 空间位置和透视响应

必须实时更新。

对于世界空间面板，尽可能直接使用 Three.js 场景坐标和相机矩阵，让相机旋转时自动产生正确的透视变化。

对于需要计算屏幕投影坐标的面板，应与渲染帧同步更新。

不能出现悬浮UI停留在原位置、相机已经转动但UI过一会儿才跟上的现象。

### 2. 巨幕激活反馈

必须即时响应。

当新的巨幕满足激活条件时，在当前帧或下一渲染帧更新：

- 当前激活巨幕
- 对应UI高亮
- 动作标题
- 视频序号
- 动作介绍内容
- 关联悬浮面板的显示状态

禁止等待相机停止旋转。

### 3. 面板过渡动画

只允许非常短的视觉过渡。

推荐参数：

- 空间位置响应：逐帧同步，不添加人为延迟
- 高亮反馈：立即更新
- 面板显隐：80—120ms
- 文字内容切换：立即切换，或采用不影响响应感知的极短过渡
- 点击、悬停反馈：下一渲染帧可见

动画必须使用时间增量计算，避免不同刷新率下速度不一致。

## 三、实时视角识别算法

请在渲染循环中根据相机方向判断当前观察对象。

计算相机方向与四面巨幕的空间关系。

根据以下因素判断当前激活巨幕：

1. 相机观察方向
2. 巨幕中心位置
3. 巨幕法线
4. 当前视锥可见性
5. 当前巨幕与候选巨幕的夹角差异

### 防抖要求

不要使用时间延迟防抖。

改用 Angular Hysteresis（角度迟滞）。

例如：

只有候选巨幕的观察方向匹配程度比当前巨幕明显更优时，才切换激活状态。

建议以5°—10°作为初始迟滞参数，并根据实际四面巨幕布局调优。

这个参数不是固定切换角度，而是减少边界抖动的差值门槛。

这样可以保证：

- 用户快速旋转时，UI立即响应。
- 用户停留在两个巨幕交界处时，UI不会反复闪烁。
- 不需要人为等待500ms。
- 不会因为视频尚未加载完成而延迟空间反馈。

## 四、使用逐帧更新机制

优先复用现有 Three.js / React Three Fiber 渲染循环。

React Three Fiber 可使用 useFrame。

原生 Three.js 可使用现有 requestAnimationFrame 渲染循环。

要求：

- 相机更新与空间UI更新保持同帧同步。
- 不要为UI重复创建额外的无限渲染循环。
- 不要在每一帧触发整个React页面重新渲染。
- 高频位置变化优先通过对象引用和矩阵更新完成。
- 只有激活巨幕ID等离散状态真正变化时，才更新相关应用状态。
- 避免频繁创建新对象、材质与几何体。
- 不要在渲染主线程执行昂贵的视频重建或贴图处理。

## 五、空间UI必须跟得上快速操作

必须测试以下场景：

**场景A：用户快速向左拖动90°**

左侧介绍牌立即按照真实空间透视移动。

当前巨幕信息立即根据视角改变。

不能出现UI滞后、跳跃或突然传送。

**场景B：用户连续旋转180°**

每块世界空间面板保持正确的空间位置。

随着相机旋转自然进入或退出视野。

不允许所有面板同时追着相机旋转。

**场景C：用户快速来回旋转**

激活面板及时切换。

采用角度迟滞防止边界闪烁。

不允许因为延迟队列而显示过时内容。

**场景D：用户拖动期间点击UI**

UI命中区域准确。

点击悬浮面板时，相机不能同时被误拖动。

**场景E：醒狮自动旋转**

醒狮自身旋转不触发相机观察状态变化。

## 六、性能验收目标

桌面设备目标为60FPS，支持高刷新率显示设备。

在60Hz显示环境下：

- 单帧预算约16.7ms。
- 相机变化到空间UI反馈的目标延迟不超过一个渲染帧。
- 避免明显掉帧、位置抖动和视觉拖尾。
- 当设备性能不足时，应优先降低装饰光效，而不是降低UI响应频率。

不要通过增加延迟来解决性能问题。

## 七、视频切换与UI响应分离

UI反馈必须立即执行。

视频资源准备、解码和播放切换可以异步处理。

不得因为等待视频播放成功，导致当前巨幕高亮和信息面板迟迟不更新。

如果视频切换需要额外处理，先立即显示正确的UI状态，再异步完成对应播放器操作。

必须保证用户快速连续切换巨幕时，过期的视频异步操作不会覆盖最新的选择。

## 八、最终验收标准

所有悬浮UI必须达到：

**视角转动即响应，空间透视逐帧同步，巨幕激活立即反馈，没有人为等待时间，不因视觉动画拖慢交互。**

最终效果应该像真实VR空间中的投影界面，而不是一个需要等待相机停止后才重新布局的网页。

请优先检查并修改现有UI中的 debounce、setTimeout、transition-duration、相机状态监听以及世界坐标投影更新逻辑。

直接完成代码修改，并通过实际拖动相机验证，而不是仅描述实现方案。
