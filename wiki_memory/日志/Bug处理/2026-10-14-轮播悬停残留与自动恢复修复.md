# 轮播悬停残留与自动恢复修复

## 目标与基线

用户反馈轮播偶尔停住，切换应用后才恢复。本轮由干净`main 1a8ca69`开始，保留已交付的照片视觉、点击下一张、悬停微放大、键盘暂停、五项设置和延时恢复规则；只验收电脑端。未改媒体、依赖和资产清单。

## 可复现原因

1. 真实Chrome中在前景照片顶部内15px悬停，再向上滚65px：照片已经移离静止指针，指针仍在整块画廊内，没有pointerleave或pointermove触发重测，React一直保持`focused=true/index=0`。只移动1px就能恢复，切应用触发的可见性清理也符合用户症状。
2. 暂缓引擎模块，在loading期间移入静态按钮，加载为ready后移开：按钮的mouseleave因ready分支跳过，引擎内部focused原本false也不会通知React清理，旧悬停持续锁住自动播放。
3. 第三张窄照片外侧停住鼠标，自动切换第四张较宽照片：旧代码在过渡结束用lastPointer获取新悬停，即使没有新的用户输入也会停在index=3。

对应三条正式测试在修复前全部稳定失败，15秒断言期间始终收到`data-culture-focused=true`；输出归入忽略的`tmp/e2e-carousel-stability-before/`。

交接补强时还用精确时序注入确认commit→普通effect之间的新pointerout/leave会被旧坐标覆盖。新增正式竞态测试在同步化前稳定失败，16.2秒内又停在focused/index0；该事件为人为注入，不冒称真实物理鼠标精确复现，输出为`tmp/e2e-carousel-handoff-race-before/`。

## 修复

- 服务捕获滚动，并在容器/窗口尺寸变化后复核已有命中；窗口高度变化未触发ResizeObserver时也能释放。命中须位于可见视口且elementFromPoint仍为当前画布，避免遮挡后的旧坐标继续聚焦。
- window blur、pointercancel、离开文档清指针和已有悬停；新增监听在dispose成对移除，不增加持续RAF或轮询。
- 过渡结束只释放失效悬停，不让自动到达的照片凭旧指针坐标新建暂停。
- onReady先清理静态按钮持有的旧暂停，ready同次DOM提交的layout effects先setActive，再将按钮最近真实指针坐标一次性交给服务syncPointer重新命中验证；仍在主图内保持暂停，实际移开后恢复，旧坐标不会延后覆盖新输入。失焦清交接坐标，避免仅清暂停导致合法悬停被取消。计时hook、设置默认值及减少动态/关闭自动的抑制行为保持。

环境：Windows PowerShell、Node v24.16.0、npm12.0.1、Chrome通道；基线加本轮修改。

- 旧代码三项回归和普通effect交接竞态各有失败证据；交接同步化后首页电脑专项17/17通过（1.6分钟）：`PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/home-culture.spec.js --grep-invert 手机 --output tmp/e2e-carousel-stability-final-dev`。新增七项覆盖上述三处、交接竞态、只改视口高度、显式blur/pointercancel、连续三个完整自动循环和滚出/返回；循环同时检查文字id与画布截图变化。其后将活动状态更新也排在同次layout交接前，最终代码以生产回归核对。
- `npm test`：10/10通过，632.129ms，原177条资产未改。
- 加载测试增加ready后静止2.3秒仍保持暂停，再移开才恢复的断言，避免为了消除残留而破坏合法悬停。
- 最终`npm run build`：70模块成功，919ms；轮播服务6.38kB（gzip2.92kB），共享Three506.53kB（gzip128.94kB），既有超过500kB提示保留。

## 边界与恢复

- blur/cancel测试显式派发生命周期事件，未冒称真实OS Alt+Tab已测。Headless Chrome的bringToFront及CDP最小化命令未改变visibilityState或产生blur，不能用来证明真实应用切换。实际滚动、加载和静止指针根因已通过真实页面事件验证。
- 5173服务曾缓存旧service，touch后HTTP确认releaseInvalidFocus已进入实际运行模块；component的Vite编译会去注释，须检查onReady函数本身，不能用注释字符串判断是否刷新。
- 当前没有本轮遗留功能开发；若再出现异常，记录`data-culture-status/focused/index`、加载阶段、指针/滚动位置，按正式回归复现后再修，不用强制重启掩盖用户悬停。真实OS切应用、其他浏览器和GPU量化需在相应环境另行验证。
