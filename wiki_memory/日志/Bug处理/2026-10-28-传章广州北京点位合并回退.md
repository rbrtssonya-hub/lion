# 传章广州北京点位合并回退

## 现象与根因

用户反馈广州、北京的点位看起来没有变化。当前 5173 端口的 Vite 服务确实运行于 F 盘工程；源码中的广州 `[480, 314]`、北京 `[638, 210]` 也是旧锚点，所以不是浏览器缓存。

前一提交 `9a0afc5` 曾将两点调整到广州 `[505, 293]`、北京 `[628, 198]`，但随后的合并提交 `2df2c8a` 在 `SpreadMap.jsx` 与地图回归测试中保留了远端旧版本，因而实际合并树撤销了这两项修改。合并也移除了对应的点位审查说明。

## 修复

- 将广州和北京像素锚点重新设为用户红框位置，邮票标签位置保持不变。
- 恢复覆盖十二个城市的地图圆点锚点回归，并恢复十二城地理核对说明。
- 保留 `spread.js` 中城市经纬度；地图背景是 Blender 透视示意，不是 GIS 投影，画布点位为图像校准锚点。

## 验证

在 Windows、基线 `2df2c8a` 加本次工作区修改上：Playwright Edge 通道先复现广州旧坐标导致断言失败，再在修复后通过；地图渲染与邮票 E2E 共 6/6，通过 `npm test` 140/140（含十二城坐标值回归），`verify.mjs` 通过，`npm run build` 成功（395 模块；已有 648.95 kB chunk 体积提示）。5173 服务返回修复后的广州、北京锚点。

## 查看

当前开发服务器已直接返回修复后的地图组件；若已打开的页面没有触发热更新，刷新页面即可重新加载。
