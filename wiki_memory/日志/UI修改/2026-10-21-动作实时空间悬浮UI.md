# 动作实时空间悬浮UI

## 目标与实施位置

本任务在用户当前 E:/数字媒体竞赛/张钧儒/lion、`codex/huangzhi_ARUI`、基线 `a3898e5` 实施，起始跟踪文件干净，只有用户 `model/` 未跟踪。用户明确要求按附件参考图与完整实时响应提示词直接修改并实际拖动验证；前阶段“只在F盘”“动作冻结”“仅换首页视频”等属于当时任务范围，不阻止本轮E盘动作开发。本轮不主动合main、同步F盘或重打EXE，交付按根AGENTS普通提交推送当前分支，保留其他任务内容。

## 已实现

- React/CSS/SVG绘制深茶半透明底、双层金边、云纹角饰、宋体和章印；左侧“四面观狮”标题牌、四幕编号/播放牌与各幕独立世界解读牌，底部操作提示/椭圆罗盘/自转及平面切换贴合参考。标题与解读牌固定世界偏转+20°/-16°，不是跟随相机的billboard；当前幕解读牌即时显示。保留四站选择、播放进度、单主音轨、全屏与平面回退，原顶栏继续复用。
- 新 `actionTheaterSpatialUI` 初始化时缓存真实巨幕中心、法线、视锥边界与面板世界矩阵。在现有Three RAF相机更新后，以 `viewport × projection × view × world` 写CSS `matrix3d`；世界牌透视和浏览器命中共用矩阵，法线/视锥/四角负责显隐，隐藏元素inert。高频更新只改引用/矩阵，只有激活ID变化才 `flushSync` 提交React标题/编号/导航/解说，不新增UI无限RAF。
- 删除180ms观察停留、OrbitControls惯性、450ms亮度过渡与460ms旧解说残留；默认7°角优势迟滞在候选满足真实空间资格的当前帧切换。主动点击转幕的镜头导航为120ms，UI始终随真实相机而不等待镜头完成。世界位置、文本和高亮没有人为等待或位置缓动。
- 四个稳定视频及原每路revision/当前ID发布过滤保留，UI不依赖加载、解码或play promise完成；过期播放操作不能覆盖新选择。新增开关只暂停/继续醒狮自转，不转相机。平面模式保留世界DOM并隐藏/暂停3D，恢复复用同组牌；卸载沿原生命周期释放资源、监听与动画。
- 世界viewport翻转CSS Z轴，移除额外CSS背面判定避免完整投影被误判。实际截图发现900px两侧牌裁切、1366px短窗解说与底栏遮挡，仅在viewport resize时重排缓存锚点收拢/抬高，转相机时世界位置不变。此前“小于521px设置推开裁切”的审查是假设：共享布局实际要求push余宽>=900px，<=560px紧凑单列只防御极窄电脑窗口，不扩展手机专项。
