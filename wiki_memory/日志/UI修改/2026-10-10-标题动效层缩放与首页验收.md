# 标题动效层缩放与首页验收

## 目标与已确认选择

接续main `281db55`，开始时工作区干净。此前首页导航、按钮、辅助文案、装饰与五个模块已经交付，PNG标题受“只改font-size”限制而未调整；当时状态见 [[日志/UI修改/2026-10-09-首页参考图视觉重构.md|前轮日志]]。

用户于2026-10-10明确选择“动效层缩放的方式调整标题比例，采用这个效果”，并再次提供最终首页参考图。该确认只放宽标题尺寸的实现方式：允许等比例缩放，继续保留原图片笔刷字形、颜色、两行排布、外层容器、定位与原有悬浮/鼠标跟随；不更换背景、视频或文案。当前标题仍是PNG加CSS/JavaScript动效，没有新建Cubism模型。

## 实现与修正

- 仅调整 `src/styles/home.css`：标题图片在原鼠标平移后叠加等比例scale，以左下沿为锚点，保持标题容器及按钮原位置。没有修改 `TitleMotionLayer.jsx` 或浮动关键帧。
- 默认大屏倍率1.45；宽度不超过1600px为1.12，不超过900px为1.06，不超过560px保持1。倍率由实际截图与标题、导航、按钮的空间选择，不将同一放大倍率强加到窄屏。
- 断点检查发现1601×900下底部网格项被最小内容高度撑到页面下方约2.17px；补充 `min-height: 0` 约束，保持导航栏高度和设计，并确认实际图标、编号、标题和说明均完整可见。
- 原透明标题、首页视频、入场视频和整体GLB均保留，未替换或重写二进制资源。

## 实际验证

环境为Windows，系统Node.js v24.20.0/npm 11.19.0，浏览器为Chrome通道；验证适用于 `281db55` 加本次CSS改动。

- `npm test`：6项全部通过，包括归档二进制大小/SHA256、媒体配置与原资源包检查。
- `npm run build`：成功；Three.js原有567.53kB分包提示仍存在。
- `npm run test:e2e -- --output=tmp/e2e-title-scale-dev`：8项通过（13.7秒）。
- `npm run test:e2e:preview -- --output=tmp/e2e-title-scale-preview`：8项通过（12.6秒）。覆盖顶部六章、底部五个入口、搜索/菜单、视频转场、整体/结构以及错误回退。
- 临时审查脚本 `tmp/home-title-scale-audit.mjs` 检查11种视口：2560×1440、1920×1080、1601×900、1600×900、1280×720、901×720、900×720、560×760、390×844、375×667、320×568。标题与其他UI没有相互重叠或裁切，页面无横向溢出，底部入口及其文字/图标完整可见。
- 五种尺寸的改动前后计算样式/边界对照证明：标题外层、文案容器、CTA、辅助文案与视频舞台全部保持原样；图片只改变授权的scale及其锚点。可见宽高按相同倍率变化，左侧与下沿锚点一致。
- 正常动效状态下验证鼠标左右移动仍产生标题响应，`titleFloat`持续运行且变换随时间变化；点击“探索更多”仍进入入场视频。减少动态效果的浏览器偏好保持原逻辑。
- 实际查看1920×1080、2560×1440、1280×720与390×844截图。截图和尺寸对照位于忽略目录 `tmp/home-ui-before-title-scale/`、`tmp/home-ui-after-title-scale/`，不进入部署资产。
