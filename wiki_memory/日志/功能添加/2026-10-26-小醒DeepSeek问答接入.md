# 小醒 DeepSeek 问答接入

用户确认先完成智能问答方案，再接入 DeepSeek；随后在本机填好 API 密钥并要求继续。密钥未在聊天中发送，保存在 Git 忽略的 `.env.xiaoxing.local`，只由 Node 服务端读取。

## 完成内容

- 启用 DeepSeek Chat Completions 配置，默认地址 `https://api.deepseek.com`、模型 `deepseek-flash`，在线模式由 `XIAOXING_OFFLINE=0` 控制。
- 更新 `.env.xiaoxing.example` 与 `docs/XIAOXING_AI.md`，记录本机/部署的密钥边界、服务端配置和在线/离线切换。
- 修正服务端问答章节白名单，允许 UI 使用的 `spread` 章节键。
- 保留本地知识检索、来源 ID 过滤、模型失败时本地回答等既有保护；不把凭据传给前端。

## 验证与边界

确认本机密钥存在但不输出其值，`XIAOXING_OFFLINE=0`、模型为 `deepseek-flash`。真实 Node HTTP 请求和 Chrome 生产预览问答均返回在线回答及可信本地资料来源，浏览器最终记录无页面异常。详细请求、端口和实际观察见[接入实证](../../../source/references/xiaoxing-deepseek-2026-10-26.md)。

本次续接未重跑自动化测试或构建。旧 EXE 未重打包、未联网验收；公开分发仍需服务端 HTTPS 网关，不能把提供方密钥发给观众。
