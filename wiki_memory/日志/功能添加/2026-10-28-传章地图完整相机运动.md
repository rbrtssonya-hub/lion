# 传章地图完整相机运动

用户纠正此前三个静帧不能满足运镜要求。网页现在播放用户 Blender 场景 1–204 帧的实际渲染，24 fps、20:13；广东、中国、世界分别对应第 1、100、204 帧的静止区间。切换层级正向或反向走完相机轨迹，直达世界经过中国停顿，快速更改目标从当前画面继续。移动期间隐藏固定案例点，停稳恢复；减少动态偏好、视频错误回退对应静帧，离页暂停资源。原工程是三维场景，网页使用渲染视频呈现原运镜而非实时三维相机。

两段运动逐帧渲染；93–111 与 186–204 帧经检查场景和驱动相同，分别复用同段第 100 与 200 帧，保留原帧数与停顿。两份视频各 204 帧、1000×650、24 fps；逐帧解码与对应 PNG 的 RGB 平均误差正向 1.98、反向 1.99（0–255 通道，视频压缩），最大帧均值分别 2.33 与 2.43，详见 [逐帧比对](../../../source/references/spread-map-motion/frame-comparison.json)。源素材与重建步骤见 [README](../../../source/models/spread-map/README.md)。

基于 `dd16499` 与本任务改动，2026-10-28 Windows：`npm run build` 通过，保留既有 Three.js 大包提示；`npm test` 137/137 通过；真实视频下独立 28474 开发服务四份地图 Playwright 专项 19/19 通过，覆盖前进、跨层、回看、中途反向、媒体错误、卸载和减少动态。生产预览 `node scripts/review-spread-map-motion.mjs` 在 1440×900 捕获两段前进与回看、无页面错误，见 [审查记录](../../../source/reviews/spread-map-motion/2026-10-28/capture.json)。初次审查脚本向沙盒 iframe 注入 sessionStorage 导致两条错误，限定顶层窗口后重跑通过。桌面以外未专项验证。
