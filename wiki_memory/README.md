# 工程记忆

本项目由用户明确指定采用 `standard`。视频入口、三维场景、章节内容、素材制作与验证的维护节奏不同，分别维护概览、架构、约束、待办和问题；五个文件必须保存可核实的恢复上下文，不能以文件数或空模板表示完成。

`wiki_memory/` 直接位于工程根目录，本页是唯一记忆导航；[AGENTS.md](AGENTS.md) 保存维护协议。保留中文专题名称，不再维护第三份导航文件。位置与导航的用户选择见 [[决策/ADR-004-根目录记忆与README导航.md|ADR-004]]。

开始任务先确认分支、revision 和未提交改动，再依次读项目概览、当前约束、当前待办；涉及模块时读架构、问题和相关有效决策/知识。当前事实以源码、配置和用户要求核实，日志仅追溯当时事件。

## 日志分类

本项目采用 standard，日志按主要工作类型放入下列真实目录，文件名仍为 `YYYY-MM-DD-短标题.md`。日志的 `kind` 与所在目录一致；跨类型任务选择主要结果，不复制同一篇日志。

| 日志目录 | kind |
| --- | --- |
| [功能添加](日志/功能添加/) | feature |
| [UI修改](日志/UI修改/) | ui |
| [Bug处理](日志/Bug处理/) | bug |
| [工程讨论](日志/工程讨论/) | discussion |
| [测试验证](日志/测试验证/) | test |
| [工程维护](日志/工程维护/) | maintenance |

六个目录保留 `.gitkeep`，使尚无事件的分类也可随工程迁移。根级 [工作日志 MOC](日志/MOC_工作日志.md) 统一汇总各类日志；已有两篇迁移/记忆整改日志按其 `maintenance` 类型移入工程维护，仅修复引用，不改当时事件正文。当前分类整改见 [[日志/工程维护/2026-10-09-标准日志分类整改.md|分类整改日志]]。
