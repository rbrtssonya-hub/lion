# 完整对话修改提交与推送

## 选择与依据

决策者：用户，2026-10-09。lion 每次完整对话涉及项目文件修改时，结束前同步相关工程记忆、执行适用验证、审查 diff、提交任务改动并推送当前分支的配置 GitHub upstream。该持续授权由用户直接指定，日常提交与推送无需再次确认。

## 执行范围

- 显式暂存本任务路径或 hunk，包括同一任务尚未提交的修改；保留其他任务的既有改动和暂存内容，不自动提交整个工作区。
- 只读对话或无文件修改无需空提交。
- 报告 commit 和 push 结果。验证、冲突、凭据或远程变化阻止交付时保全工作并报告原因，不强制推送。
- 历史日志保留当时的本地授权和未提交事实；当前协议与状态应用新约定。此决策增加交付约定，不替代根目录记忆、标准日志分类或前端架构选择。

## 落地与验证

根 `AGENTS.md` 保存执行规则，记忆协议和当前约束链接此选择。本次将此前整理的工程记忆与新约定一起纳入版本管理；React/source 的既有迁移改动归原任务保留。实际验证与交付范围见本次工作日志。
